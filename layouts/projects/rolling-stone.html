Project overview

Built for quick runs on different devices

The Rolling Stone is a 3D endless runner built around responsive movement, increasingly difficult obstacle sequences, persistent progression, and global leaderboards.

The stone moves forward automatically while the player steers, jumps, collects coins, and uses temporary power ups. I made the game as a solo project because I wanted to build something that could work naturally with desktop and mobile controls.

Controls and game feel

Movement that works across browser inputs

Instead of fixed lanes, the player has free lateral steering and direct control over jump height. Holding jump produces a higher arc, while releasing it early creates a shorter hop.

The controller combines steering smoothing, air control, jump buffering, coyote time, and separate acceleration and response tuning. The HTML5 release supports rebindable keyboard controls, controllers, touchscreen input, and accelerometer steering.

A run ends when the stone falls from the track or hits an obstacle without an active Phase Shield. Distance is the primary score, while collected coins become currency.

Segments and difficulty

Handcrafted obstacles arranged for each run

The track is assembled from 14 handcrafted segment prefabs rather than procedurally generated geometry. The current set includes rotating and lateral obstacles, underpasses, crushers, falling hazards, jump sections, recovery areas, and safe floor sections.

A segment director manages weighted selection, difficulty tiers, minimum distance rules, repeat cooldowns, difficult segment streak limits, and recovery sections. Object pooling lets segments be recycled as the run continues.

Difficulty rises in two ways. Forward speed follows a tuned progression curve, and harder segments become more common as the player reaches greater distances.

Progression

Reasons to return beyond one high score

Coins earned during runs can be spent on visual customization. The current build includes 16 completed cosmetic choices across stone skins, trails, and obstacle themes. Cosmetics do not provide gameplay advantages, and there are no permanent mechanical upgrades.

I also built 15 achievements and 24 daily and weekly missions that the player can complete. These systems reward distance milestones, completed runs, coin collection, power up use, and cosmetic unlocks while giving players both immediate and longer term goals.

Coin Magnet, Phase Shield, and Speed Rush are the three power ups currently available during runs.

Connected systems

Saving progress and protecting global rankings

Unity Gaming Services handles anonymous authentication, moderated display names, Cloud Save, and two global leaderboards. Best Runs ranks each player's best distance, while Richest Players ranks lifetime coins earned.

Progress is stored locally and synchronized with the cloud. The browser release uses a cloud backed anonymous profile, but it does not promise recoverable progress across devices because Unity Player Account linking is not supported in the current WebGL build.

I implemented layered leaderboard protection using local currency integrity checks and Cloud Code validation. Run submissions are checked before trusted distance and lifetime coin totals are committed, with invalid or duplicate submissions rejected.

Players also have the option to hide their identity by going to the settings and checking off Leaderboard Privacy, cosmetics, and achievement count while keeping their score and ranking visible.

Playtesting and iteration

Using player feedback to shape the game

Repeated playtests identified slow early pacing, inconsistent jump control, frustrating obstacle combinations, and limited replay ability.

I responded by implementing variable jump height, a faster initial game pace, smoother steering, jump buffering, coyote time, distance gated obstacles, repeat obstacle prevention, and recovery segments. I also added clearer controls, an interactive tutorial, cosmetics, achievements, missions, and global leaderboards.

Because the controller affects obstacle timing, speed, and the overall difficulty curve, each movement change had to be tested against the rest of the game rather than tuned in isolation.

Retrospective

What I would improve next

Development structure

If I rebuilt the project, I would establish main, development, and feature branches from the start and use pull requests for integration. I would also split the player controller into smaller systems for input, lateral movement, jumping, forward speed progression, difficulty, and temporary modifiers.

Active development

Future updates are planned for the UI and UX, additional obstacle segments, more cosmetics, environment themes, new gameplay features, and game modes beyond the current endless mode.
